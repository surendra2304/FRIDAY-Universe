## 1. AutoClip — REJECT

**What it is.** `zhouxiaoka/autoclip` — "AutoClip｜一个链接，一键出片" — open-source AI video clipping and content repurposing. Repo: https://github.com/zhouxiaoka/autoclip — Homepage: https://zhouxiaoka.github.io/autoclip_intro/en/ (Not the unrelated `Farkoal2128/AutoClip-MVP`, `Rohitpati8464/autoclip`, or PyPI `ass-autoclip`.) Paste a YouTube/Bilibili link, drop a local file, or import a live-stream replay, and it finds the best moments, tracks the speaker, burns in captions, generates covers and exports clips for TikTok, Shorts, Reels and others.

**How highlight detection works (concrete).** Text-first, not vision-first: the video is treated as a transcript and an LLM reads the subtitles like a script. A 6-step pipeline (`step1_outline.py` … `step6_video.py`): (1) outline extraction from SRT (chunked ~30-min blocks, LLM extracts topic outline); (2) timeline extraction (LLM locates precise start/end per topic); (3) highlight scoring (LLM, criteria in an external prompt file, not hardcoded); (4) title generation; (5) topic clustering; (6) FFmpeg render (vertical crop / speaker framing, burned-in captions, export kits). Subtitles from platform captions or a supplied `--srt`; otherwise local Whisper / SenseVoice or cloud ASR (Alibaba Bailian — audio uploaded). The README is explicit that subtitle-only scoring misses visual-only moments ("For gameplay or low-dialogue streams, enable a vision-capable model"). v1.6 adds a "Game Highlights" path (vision/OCR, more model cost). Outputs up to 10 ranked clips per run, plus a desktop app, Docker web UI, CLI and an MCP server.

**Version observed (2026-11-25):** main `2f511907a72cbfbb8d86639f6441967b826acb6a`, 1,547 commits, 15,706 stars, 2,292 forks, created 2025-07-08, 23 releases. Latest release entry is Desktop v1.6.1 (pre-release); v1.6.0 is the latest full release. No Linux desktop build (macOS arm64 / Windows x64 only). **PyPI is behind GitHub:** `autoclip-mcp` latest is 1.5.7.post1; the trial tested 1.5.7, not 1.6.x. Maintainer benchmarks (Apple Silicon, qwen-plus cost, excl. cloud ASR): 1h 43m video with subtitles → 7.5 min / 10 clips, ~¥0.09; 2h 52m without subtitles (local Whisper) → 29.5 min / 10 clips, ¥0.20.

**License and cost.** Software licence **MIT** (repo metadata, `LICENSE` file, README: "Free, MIT-licensed, zero subscriptions — everything cuts and renders on your machine"). **But the intelligence is metered:** the README FAQ states "Cloud analysis, transcription, and AI covers use your own API keys at provider rates." Default provider is DashScope (Qwen, model `qwen-plus`); others include OpenAI-compatible, Gemini, DeepSeek, SiliconFlow, Kimi, GLM, Grok. The fully-free path is local analysis via Ollama (default `http://localhost:11434/v1`, model `qwen2.5:7b`) or LM Studio, plus local Whisper/SenseVoice — which needs a local 7B model download (~220 MB first transcription component), enough RAM/CPU/GPU, and 16k+ token context. No subscription, no watermark, no export paywall in the tool itself. Solo-maintained; desktop installers unsigned / not notarised (issue #119). **Cost verdict:** software free (MIT); running it as designed = pay-per-use LLM calls, or a heavyweight local-model setup the fleet does not have.

**Runtime and dependencies.** Python 3.10+ (3.11 recommended) + TypeScript/React + Rust (Tauri 2 desktop shell); FFmpeg/ffprobe on PATH; yt-dlp for ingestion; faster-whisper or SenseVoice (local) or Alibaba Bailian cloud ASR; LLM via DashScope/OpenAI-compatible/Gemini/DeepSeek/Ollama/LM Studio; full Docker stack is FastAPI + Celery + Redis + SQLite + React. **Fleet fit: poor.** VyralX's resident service runs under a ~180 MB cap on ~956 MB fleet VMs and its pipeline modules are pure-stdlib Python 3.10 plan-only code; AutoClip is a whole second stack — the trial venv alone was 327 MB before any model download.

(3) It is a second stack, not a library — FastAPI + Celery + Redis + React + Tauri, or a 327 MB CLI venv plus model downloads, against pure-stdlib Python 3.10 plan-only modules under a ~180 MB resident cap; there is no small embeddable "highlight scorer" to lift out. (4) Its ingestion model conflicts with the fleet's constraints — download-first (yt-dlp) with no footage-provenance gate, while VYR-068 is own-content only and the fleet download path is broken/off-limits under the owner stop order. (5) Version/maintenance risk is real but secondary: solo maintainer, unsigned installers, PyPI (1.5.7.post1) behind GitHub releases (v1.6.1 pre-release). **What to do instead (adapt, not adopt):** if the team ever wants semantic scoring, port AutoClip's *staging* — outline → timeline → score → title, with scoring criteria in an external prompt file — as a plan-only step onto the fleet's existing free-tier LLM keys, gated by `held_render_qa` and the existing review-first flow. That borrows the idea without importing the stack, the metered dependency, or the publish-first posture. That is a future decision for the coordinator, not a recommendation to build now.

## 2. OpenShorts — ADAPT (do not adopt the platform)

**What it is.** `mutonby/openshorts` — open-source, self-hosted AI clip generator: feed it a long video (YouTube URL via yt-dlp, or a local upload) and it returns finished 9:16 vertical clips for TikTok / Reels / Shorts — reframed, captioned, with a hook line, a virality score and per-platform titles. It calls itself "the open-source OpusClip alternative". Repo: https://github.com/mutonby/openshorts — Homepage: https://www.openshorts.app/ — Self-hosting guide: https://www.openshorts.app/self-hosted-ai-clip-maker

**How it works (concrete, verified against source at the observed commit).** (1) Ingest — YouTube URL (yt-dlp) or local upload. (2) Transcribe — faster-whisper (or Parakeet on GPU) with word-level timestamps (default model `small`, `large-v3-turbo` on GPU). (3) Scene detection — TransNetV2 neural shot-boundary detector by default (torch), falling back to PySceneDetect `ContentDetector`. (4) Moment-pick — Google Gemini 3.1 Flash-Lite receives the timestamped transcript + scene boundaries and returns 3–15 moments of 15–60 s, each with a virality score; a local LLM via `LLM_BASE_URL` (Ollama / LM Studio / vLLM, 7–8B+ recommended, 16k context) can replace Gemini. (5) FFmpeg precise clip cutting. (6) Reframe to 9:16 — per scene, one of four layouts (`reframe_v2.py`, 936 lines): **TRACK** (MediaPipe BlazeFace face tracking with a smoothed cameraman trajectory, per-frame crop-x via ffmpeg `sendcmd`, YOLOv8 person-box fallback), **GENERAL** (blurred-background bed), **SPLIT** (two speakers stacked vertically, captions on the seam), **SCREENCAST** (screen above presenter / webcam inset). Output 1080×1920 (delivery floor `DELIVERY_MIN_WIDTH = 1080`; a 720p source's crop is upscaled, never shipped sub-HD). (7) Effects — word-level subtitles burned in (SRT or karaoke ASS), AI hook overlay, Gemini-generated FFmpeg filter effects. (8) Dubbing (optional) — ElevenLabs, 30+ languages with voice cloning; the dubbed track is re-transcribed so subtitles match. (9) Publish (optional) — S3 backup + Upload-Post distribution; Autopilot (Cloud, paid) clips every new channel video automatically. It also ships a clip editor with word-level cuts (`recut.py`), an AI Shorts / UGC creator (fal.ai, pay-per-use ~$0.50–2.00/video), YouTube Studio one-click publishing, and a built-in MCP server + REST API + CLI.

**Version observed (2026-11-25):** main commit `29ccbf372d6b3a99586ba7de2bf49d426bc2c69b`, 749 commits, 9,867 stars, 2,061 forks, **0 releases, 0 tags** (no version number exists — pin by commit), created 2025-12-19. GitHub flags the repo itself as a fork (parent not named on the fetched page); similarly-named `tayonike/openshorts.-ugc` and `faris-sait/openshorts` are forks/copies.

**License and cost.** Core application **MIT** (verified first-hand from the cloned tree's `LICENSE`, "Copyright (c) 2024 OpenShorts"; GitHub metadata agrees). **Exception:** the `cloud/` directory (billing, managed keys, hosted-service infrastructure behind `BILLING_ENABLED`) is source-available under a separate **OpenShorts Commercial License** — readable/modifiable/self-hostable for personal or internal use, but not offerable to third parties as a paid/hosted service. Self-hosting the core never requires that directory; VyralX would not touch it. Self-hosted cost $0 in software (free forever, no watermark, no cap, no per-minute meter); you pay the machine, electricity, time, and API usage: Gemini free tier for individual use, under $0.01 per 10-min video beyond it (replaceable with a local LLM, $0); ElevenLabs dubbing pay-per-use (free tier available) — **paid path, closed under FREE ONLY**; fal.ai AI Shorts pay-per-use — **paid, out of scope**; Upload-Post 10 free uploads/month then pay-per-use — **paid, and forbidden on safety grounds**; AWS S3 backup optional ~$0.023/GB. Hosted Cloud paid from $12/mo (free plan = first video up to 60 min then 20 min/mo, watermarked) — **not usable under FREE ONLY**, and it would send footage to a third party. **Cost verdict:** the clipping core passes FREE ONLY (MIT, $0 self-hosted); dubbing, AI-Shorts and auto-publishing are paid and must stay disabled.

**Runtime and dependencies.** Python 3.11 (Docker image `python:3.11-slim`, pinned by digest), FastAPI + React 18 / Vite. Install method: **Docker + Docker Compose only** (`docker compose up --build`; dashboard `:5175`, API `:8000`); no supported bare-metal install path. Hardware: **8 GB+ RAM, modern multi-core CPU**; CPU ~5–8 min to clip an 8-min video; optional NVIDIA GPU (NVENC, 8 GB VRAM) cuts that to ~1 min; GPU image ~2 GB larger. Heavy pins: `torch==2.11.0`, `torchvision==0.26.0`, `ultralytics==8.4.46` (YOLOv8), `mediapipe==0.10.14`, `opencv-python==5.0.0.93`, `faster-whisper==1.2.1`, `scenedetect==0.7`, `transnetv2-pytorch==1.0.5`, `google-genai==1.75.0`, `yt-dlp`, FFmpeg, `onnxruntime` / `onnx-asr`. Full CPU lock ~100 pinned packages. External services: Gemini (moment picking, layout picker, silent-video clipping) unless a local LLM is pointed at; ElevenLabs only for dubbing; fal.ai only for AI Shorts; Upload-Post only for publishing. **Fleet fit:** the stack is orders of magnitude above the fleet envelope — VyralX's own ports are pure-stdlib plan builders precisely because the resident service is capped at ~180 MB on ~956 MB VMs; OpenShorts needs Docker, 8 GB RAM, a multi-GB torch/mediapipe/whisper model set and Python 3.11 (fleet runs Python 3.10). **How it works (concrete, from `main_improved.py` + `scripts/`).** (1) Input — a YouTube URL (default path; `--url`), downloaded with `yt-dlp` (quality selector best/1080p/720p/480p, `--cookies-file` supported, optional YouTube-subtitle download for alignment). (3) Viral segment selection — `scripts/create_viral_segments.py` sends the transcript to an LLM backend chosen by `--ai-backend`: `gemini` (key in `api_config.json`), `g4f` (unofficial free-GPT wrapper), `local` (llama.cpp GGUF models from `models/`), or `manual` (operator pastes segments; an early issue thread confirms the manual path expects a ChatGPT-produced JSON). No-face fallback is `padding` (black bars) or `zoom` (centre crop). (5) Word-by-word captions — `scripts/adjust_subtitles.py` (`generate_ass_from_file`) builds a styled `.ass` from the WhisperX word-level JSON: modes `highlight` / `word_by_word` / `no_highlight`, `words_per_block` (default 3), `gap_limit` 0.5 s, Montserrat font, configurable base/highlight size and colour, optional punctuation removal — the "Hormozi-style" word-by-word highlight. `scripts/burn_subtitles.py` burns the ASS into the clip with FFmpeg (`subtitles` filter), trying `h264_nvenc` first and falling back to `libx264 ultrafast` at 5 Mbit/s. (6) Extras — caption translation to 10+ languages (`deep-translator`, word-by-word highlight preserved), Premiere Pro XML export (beta), Gradio WebUI (project gallery, subtitle editor), `subtitle_studio.py` (118 KB standalone subtitle tool). ## 4. Cross-cutting findings (all three tools)

1. **VyralX already owns the pipeline.** Moment-finding, scene detection, vertical crop, captions, transcription/alignment, FFmpeg render and assembly planning are all implemented in-repo, mostly as small, dependency-free, deterministic Python 3.10 modules. All three tools duplicate most of that. The evaluation found only three genuine gaps between them (see §5).
2. **All three reintroduce LLM moment-ranking that the team deliberately removed.** `shorts_live_path.py` records the decision: "The upstream LLM highlight-ranking step stays replaced by VyralX's deterministic scoring", under FREE ONLY / no-LLM-call rules. AutoClip's scoring *is* an LLM call; OpenShorts' moment-picker is a Gemini (or local 7–8B) call; ViralCutter's segment selection is Gemini/GPT-4/`g4f`/local GGUF. None offers a deterministic, key-free scoring path that matches VyralX's design.
3. **None has VyralX's machine-QA gates.** `held_render_qa.py` + `gta6_series.gate_series_episode` (caption-track count, BGM mandatory, watermark verified, loudness −24…−10 LUFS, true peak ≤ −1.0 dBFS, blank/black check, fail-closed) have no equivalent in any of the three tools. Any adopted render would still have to pass those gates unchanged — and AutoClip/OpenShorts/ViralCutter outputs would fail them as produced (no BGM handling, no watermark/provenance, no loudness gate; OpenShorts burns captions in with no sidecar discipline for the caption-track gate).
4. **All three are download-first; the fleet download path is broken and off-limits.** AutoClip and ViralCutter ingest YouTube/Bilibili URLs via yt-dlp by default; OpenShorts offers YouTube ingest the same way. VYR-068 is own-content only, and the fleet download path is broken (VYR-052: S2 cookie jar and niche guard still missing; VYR-056 leg closed as unachievable per coordinator ruling 4) under the owner stop order (2026-11-24 ~16:42 IST).
5. **None runs inside the fleet envelope.** VyralX's resident service is capped at ~180 MB on ~956 MB VMs, Python 3.10, CPU-only. AutoClip is a second stack (327 MB CLI venv before models, or FastAPI + Celery + Redis + React via Docker); OpenShorts is Docker-only, Python 3.11, 8 GB+ RAM, torch/YOLOv8/faster-whisper/MediaPipe; ViralCutter needs a CUDA GPU, torch 2.3.1+cu121, pinned transformers 4.46.3, InsightFace and Xvfb. At most they could run off-fleet (owner machine / post-ARM batch), the execution slot VyralX already reserves for rendering.
6. **All three have a publish-first or upload-shaped half that conflicts with review-first.** AutoClip offers one-click publishing; OpenShorts offers Upload-Post distribution and Autopilot (a clip a day, on its own); ViralCutter's roadmap adds direct upload to TikTok/YouTube/Instagram. VyralX's model is unlisted + review-first, renders held for the owner, loop OFF, uploader paused. Any adoption must exclude the publishing half entirely.
7. **Licences differ in a way that matters:** AutoClip and OpenShorts are MIT (OpenShorts' `cloud/` dir is under a separate commercial licence, not needed for self-hosting) — permissive, no barrier. ViralCutter is GPL-3.0 — copyleft blocks vendoring or copying its code into VyralX without GPL-licensing the derivative.
