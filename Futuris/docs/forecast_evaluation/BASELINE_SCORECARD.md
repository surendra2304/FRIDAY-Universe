## How Futuris will be judged when statsforecast lands

Re-run the identical command (`python3 scripts/run_forecast_evaluation.py` from `Futuris/`) in the environment where statsforecast is installed. Same series, same origins, same metrics — the production rows above fill in with real numbers. The bar set by this baseline: a production model earns a better-than-reference verdict on a series only if it beats the reference baselines on MASE *and* its empirical coverage@90 is at least as close to the nominal 0.90. A model whose intervals cover far below 0.90 is overconfident no matter how good its MAE looks.

## Known limits of this harness (stated, not hidden)

- Three series is a floor, not a ceiling: one monthly, one daily, one synthetic 5-minute telemetry fixture shaped like production targets. More provenanced series can be added by vendoring the file and extending PROVENANCE.json.
- The pre-existing `futuris.evaluation.backtest.BacktestEngine` is a different instrument (pipeline-level, synthetic-connector data) and has a known honesty defect this harness deliberately does not repeat: when an actual observation is missing it substitutes the forecast itself as the actual (`actual_val = f.prediction`), manufacturing zero error. Fixing or retiring that engine is a follow-up task, not part of FUT-004.
- `auto_arima` is registered in the model registry but is not in the production active candidate list (`current_active()`), so it is out of scope for this baseline.
