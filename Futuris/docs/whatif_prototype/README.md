# Futuris what-if scenario prototype (TASK-FUT-009)

**Status: prototype.** A deterministic what-if transform for Futuris base
forecast paths — not a forecasting model, not wired into the scheduler, and
not a replacement for the existing `ScenarioEngine` (which perturbs a point
forecast through the ops-wedge dependency graph). This module answers a
different question: *"given this forecast path, what does the path look like
if BTC drops 20%, rates rise 1pp, and oil rises 15% — under elasticities I
declare?"*

## What it does

`Futuris/futuris/scenarios/whatif.py`:

- Takes a base path (per-step `central / lower / upper`). The natural source
  is a real `Forecast`'s own step `intervals` — `base_path_from_forecast()`
  consumes them directly, and falls back to the single point estimate +
  range (labelled `forecast_point_estimate_single_step`) when a forecast
  carries no intervals. It never invents intermediate steps.
- Applies declared shocks. Each shock names its driver, its magnitude
  (`pct_change` percent or `pp_change` percentage points), a
  **caller-declared elasticity** (% target move per unit driver move), an
  onset step, a linear ramp, and an optional linear decay.
- Per step, shock contributions add in percentage terms and the total is
  applied multiplicatively to the base central value. Bands are rebuilt
  from the base half-widths, widened by a declared factor proportional to
  the total shock effect, with an optional declared non-negativity floor.
  Coherence (`lower <= central <= upper`) is asserted on every step; a
  total effect of −100% or worse produces an explicit warning that the
  linear-elasticity assumption has broken down, rather than a silent
  negative price.
- Prints its assumptions on the output: every shock with its elasticity,
  the additivity rule, the band-widening rule, and the statement that
  elasticities are **declared, not estimated**.

## Honest labelling (FUT-002/FUT-003 standard)

- Evidence class is inherited from the base and never upgraded: a LIVE
  base yields DERIVED (the adjusted path is computed, not measured);
  SYNTHETIC stays SYNTHETIC. `evidence_source` travels and names the
  transform (`+futuris.scenarios.whatif@v1-prototype shock transform`).
- Probability is **not** recomputed: the base probability is carried
  verbatim with `probability_status: not_recomputed_by_whatif_engine`.
- `prediction_is_not_authorization` is always true.
- statsforecast stays post-ARM (owner decision): not installed, not used,
  not worked around. The module consumes the existing honest forecast path
  only.

## Endpoint

`POST /v1/scenarios/what-if` on the already-mounted fan-chart router
(request = `WhatIfRequest`, response = `WhatIfResult`). No DB, no new
service, no scheduler wiring — prototype scope.

## Samples

Generated by running the module (`gen_samples` logic reproduced in the
TASK-FUT-009 workspace; the outputs below are the module's own renderings):

- `sample_btc_shock.json` / `.txt` — BTC −20% (elasticity 1.0, ramped over
  steps 2–3) plus a +1pp rate shock (declared elasticity −1.5) on an
  illustrative BTC path.
- `sample_oil_rates_decay.json` / `.txt` — oil +15% (declared elasticity
  0.4, linear decay over 4 steps) plus a +1pp rate shock on an illustrative
  energy-equity path.

Both samples use caller-supplied illustrative base paths and are labelled
`synthetic` in the outputs themselves.

## Tests

`Futuris/tests/scenarios/test_whatif.py` (arithmetic hand-checks, profile
shapes, coherence, labelling, validation, forecast-path extraction) and
`Futuris/tests/scenarios/test_whatif_api.py` (endpoint contract).

## Known prototype limits

- Elasticities are linear and constant per shock; real sensitivities are
  regime-dependent. That is exactly why they are printed as assumptions.
- No cross-shock interaction terms; contributions add.
- Not persisted (no ScenarioRepository write) and not exposed to FRIDAY's
  task envelope yet — both are follow-up work if the prototype is accepted.
